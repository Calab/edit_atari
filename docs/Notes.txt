I would like you to create a text editor to work on 8-bit Atari files. Some of the details are as follows:

- I should be able to build a Linux version, Windows version and possibly a Mac version. These should be standalone binaries that do not depend on the user having other requirements to install, short of the Atari font.

- It will use Atari-Regular font
- It will support Atari graphics characters and control characters. Pressing ESC before typing a control character will generate a character and NOT perform the control character action.
- Be switchable to fit window width (like a normal notepad) or to a fixed 40 columns (2 space left margin)
- Writes files in ATASCII format ($9B for EOL).
- Write Atari LST files for BASIC programs. Uses $9B EOL character, not CR+LF
- Keystrokes should make the Atari "key click" sound
- Should the the ALT key represent the Atari CONTROL key? This is to leave the CTRL key for editor functions, like Copy and Paste. For example, Pressing ALT-A will produce the character that the Atari would produce for CONTROL+A.
- Perhaps it would be better to use the left CTRL key for editor functions and the right CTRL key for the Atari CONTROL key.
- Will use PC key layout with modifications for Atari specific keys, like the Fuji key. i.e. the ESC key on the PC keyboard will be the ESC key on the Atari. PC arrow keys will produce the same keystrokes as the arrow keys on the Atari.

- Is an EXPORT command to export the ATASCII to ASCII 8 bit codepage feasable?

- Possibility of reading tokenized Atari languages - Altirra BASIC, MAC/65, Turbo BASIC XL, OSS BASIC XL & XE, FastBASIC (ATASCII), Atari Assembler Editor (ATASCII), Action! (ATASCII), etc.
- Possibility of writing tokenized Atari programs

- Google Gemini claims to be able to write a complete Python module that will decrypt Atari, Altirra, Turbo BASIC XL & Altirra Extended BASIC, OSS BASIC XL & XL, and MAC/65. Are we going to use Python? I don't know if that would be a good fit.
